## DEC-001 背景纯黑（非炭灰）
- **日期**：2026-07-13
- **背景**：早期用过莫兰迪/炭灰，用户反馈炭灰偏蓝、与红绿 K 线冲突；多次要求纯黑。
- **决策**：全局背景 `#000000`；面板级 token：`bg-secondary #0a0a0a` / `bg-tertiary #161616` / `bg-elevated #1f1f1f`；边框 `#262626`。亮色主题默认取消（REQ-UI-06 待确认）。
- **影响**：tailwind.config.js、index.css、ChartContainer、arco-theme.css 全部按此覆写；编译 CSS 已验证无 `#0f172a` 蓝灰。
- **状态**：生效中

## DEC-002 Arco 局部引入（非整体 UI 库）
- **日期**：2026-07-13
- **背景**：自写 Tailwind 组件费时；表格/弹窗/表单/日期选择器重复造轮子成本高。
- **决策**：引入 `@arco-design/web-react`，**仅**用于图标＋表格/弹窗/表单/日期选择器；主框架（黑底、画线侧栏、图表区）保持自写 Tailwind。
- **影响**：需 arco-theme-dark 覆写接入纯黑；条件单已用 Arco 实做演示。
- **状态**：生效中

## DEC-003 数据源优先级与 fallback 策略
- **日期**：2026-07（Phase 数据层）
- **背景**：单一数据源不稳定/限频。
- **决策**：优先级 同花顺 → 东方财富 → 腾讯 → Yahoo；**按方法独立 fallback**，可拼接不同源的方法结果。
- **影响**：REQ-DATA-03；provider 层需支持方法级切换。
- **状态**：生效中

## DEC-004 Rust 后端原生采集
- **日期**：2026-07（Phase 数据层）
- **背景**：用户要求采集脚本与软件一起运行自动处理，而非手动或 Node 脚本。
- **决策**：Rust `collector.rs` 原生采集（启动即采＋交易时段定时＋按需），写本地缓存 JSON；前端经 LocalCacheProvider 读取，不直接调接口。废弃 Node 采集脚本。
- **影响**：REQ-DATA-04~05；崩溃修复用 `tauri::async_runtime::spawn`（非 tokio::spawn）。
- **状态**：生效中

## DEC-008 设计语言：宽松 / 大间距 / 大圆角 / 大留白 / 偏欧美
- **日期**：2026-07-13
- **背景**：用户验收 REQ-NAV-05（图标换 Arco）后，明确整体设计取向——不要紧凑拥挤的"工具感"，要宽松、呼吸感强、圆角大、留白多的欧美 SaaS 风格。
- **决策**：Trend IQ 全产品采用**宽松大间距 + 大圆角 + 大留白 + 偏欧美**的视觉语言。具体落地方针：
  - 间距：组件/列表/导航项之间用宽松间距（如导航项 `gap-4`≈16px、容器内边距 `py-6` 起），避免 `gap-1` 这类紧凑值；
  - 圆角：按钮/卡片/面板用大圆角（`rounded-xl`≈12px 起，`rounded-2xl`≈16px 优先），避免 `rounded`/`rounded-md` 小圆角；
  - 留白：页面与区块四周保留充足空白，信息密度降低、呼吸感增强；
  - 风格：整体偏欧美现代 SaaS（非日式/拟物/密排仪表盘），与纯黑底（DEC-001）、高饱和画线（DEC-002 上下文）协调。
- **影响**：所有新 UI（导航、卡片、表格、弹窗、页内布局）默认套用此语言；既有紧凑处（如 SideNav 原 `gap-1`/`rounded-lg`）需逐步改造。首个落地为 REQ-NAV-06（导航间距改造）。
- **状态**：生效中

## DEC-009 文本颜色等级（已建立，统一遵循）
- **日期**：2026-07-13
- **背景**：用户反馈未选中导航文字"偏暗"，并询问是否有颜色等级系统。核查发现 `tailwind.config.js` 已定义三档文本色，但未在文档系统登记，团队无统一参照，易各写各的灰色值。
- **决策**：正式确立**文本颜色三档等级**（定义于 `tailwind.config.js` `colors`，全产品统一遵循）：
  - `text-primary` = `#e8e8e8`（最亮，近白）：标题 / 主文本 / 关键数字；
  - `text-secondary` = `#999999`（中灰）：次要文本 / **未选中导航与列表项**；
  - `text-muted` = `#666666`（最暗）：弱化提示、禁用态、极次要信息。
  - **规则**：导航与列表的"未选中 / 常态"项默认用 `text-secondary`（`#999999`），**不得**用 `text-muted`（`#666666`）以免偏暗；选中态用纯白 `#ffffff`。禁止硬编码新的灰色值，保证一致。
  - **例外（用户拍板）**：左侧主导航（SideNav）的"未选中"项**保持 `text-muted`（`#666666`，最暗档）**，不复用 secondary。理由：用户确认该暗度无问题（另一屏幕偏暗为个别显示差异），属有意保留的视觉层级（未选中更弱、选中纯白对比更强）。此例外仅限 SideNav 末选中态，其余导航/列表项仍遵循默认 secondary 规则。
  - 同步明确背景等级：`bg-primary` `#000` / `bg-secondary` `#0a0a0a` / `bg-tertiary` `#161616` / `bg-elevated` `#1f1f1f`；边框 `border-default` `#262626` / `border-strong` `#333`。
- **影响**：REQ-NAV-07（未选中态保持 text-muted `#666`，用户拍板不提亮；其余文本配色从此三档取，作为配色唯一参照）。
- **状态**：生效中

## DEC-010 详情页共享架构（指数详情 ≡ 个股详情）
- **日期**：2026-07-14
- **背景**：用户要求行情页 A股 大盘指数大卡片可点击跳转该指数详情页（分时/日/周/月/5日 K线）；并指出指数详情与个股详情「有相同的部分」，要求暂不与本次一并实现，等做个股详情时一起处理。为避免两类详情各造一套、后续返工，需先定架构原则。
- **决策**：**指数详情页与个股详情页共用同一套详情页框架/组件**，仅标的类型与数据源不同：
  - 统一详情页框架包含：标的头部（名称/代码/现价/涨跌）、**周期切换器（分时 / 日 / 周 / 月 / 5日）**、K 线区（KLineCharts）。
  - 路由 / id 设计须兼容两类标的（建议 `/symbol/:type/:code`，`type ∈ {index, stock}`），避免个股详情重复造轮子。
  - 指数标的走大盘指数链路（REQ-DATA-06 多源 fallback）；个股标的走个股 quote/kline 链路。
  - 周期语义：分时=当日时间分价线（**非分钟 K 线**，与 REQ-DATA-01「不支持分钟线」不冲突）；日/周/月=已收敛三周期；5日=最近 5 个交易日日 K 连排。
  - **实施节奏**：REQ-MKT-03（指数详情）**暂缓**，并入个股详情页（REQ-SYM 详情页）同批落地；个股详情开工即触发指数跳转与周期视图一并实现。
- **影响**：REQ-MKT-03（⬜ 暂缓）、REQ-SYM 详情页（待建卡）；约束详情页路由与组件设计。
- **状态**：生效中
