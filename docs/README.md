# Trend IQ 文档系统

> 本目录是 Trend IQ 项目的**规划与决策单一可信源（single source of truth）**。
> 我们基于这里规划、一步步实施，保证信息一致、目标一致、可追溯、可更新。

## ⚠️ 强制门禁（MANDATORY — 不可跳过，每轮必走）

> **这是项目最高优先级的协作纪律，高于任何"赶进度"的冲动。** 需求闭环流程不是建议，是门禁。每一轮、每一张卡片、无论需求大小都必须完整走完，无例外。

1. **不做无卡的需求** — 任何功能 / bug / 增强，先建 `cards/REQ-XXX.md` 再动手；口头需求不直接进代码。
2. **状态机不可跳跃** — ⬜待实施 → 🔧实施中 → 🧪自测中 → 👀待用户验收 → ✅已闭环。禁止从"实施"直接跳到"交付给你"，必须过 🧪自测中。
3. **自测是交验收的前置条件** — 交你验收前，必须完成自测（dev server 可达 + 无头 Chrome 抓 pageerror + `#root` 渲染验证 + 构建/`tsc` 通过 + 逐条核对 AC），并在卡「自测」段留证据。
4. **闭环需你拍板** — 只有你确认通过，卡才转 ✅；打回必须回 🔧 并附**具体意见**，禁止"无意见打回"。
5. **每轮都执行** — 哪怕一行文案、一个图标，也走完整闭环；无"太小不值得建卡"的例外。

→ 违反以上任一条，视为流程事故，必须补卡 / 补自测 / 补回写。

## 需求闭环流程（SOP：用户提需求 → 建卡 → 实施 → 自测 → 用户测 → 闭环）

1. **提需求**：用户提出一条需求（新功能 / bug / 增强）。
2. **建需求卡**：复制 `cards/_TEMPLATE.md` 为 `cards/REQ-XXX.md`，写明描述＋验收标准（AC），状态置 `⬜ 待实施`；同步在 `requirements.md` 加一行（编号/优先级/状态）。
3. **实施**：状态置 `🔧 实施中`，按卡实施；关联阶段/决策。
4. **自测（我来做）**：状态置 `🧪 自测中`。我负责验证：
   - dev server 预览可访问 + 无头浏览器抓 `pageerror`/`#root` 渲染（空白诊断法）；
   - 构建/`tsc`/类型检查通过；
   - 逐条核对验收标准（AC）是否达成。
   - 在卡「自测」段记录方法/结果/证据。
5. **用户验收**：状态置 `👀 待用户验收`。交付预览地址，用户实测。
   - 通过 → 状态 `✅ 已闭环`；打回 → 回到 `🔧 实施中` 并附意见。
6. **闭环回写**：闭环后同步 `requirements.md` 状态为 ✅ 已交付，并在 `roadmap.md` 实施记录追加一笔。

> 原则（**强制**，详见上方「⚠️ 强制门禁」）：**不做无卡的需求**；**不跳过自测直接交用户**；**不打回无具体意见的卡**。本流程每轮必走，不可省略。

## 使用纪律（保证一致性与可追溯）

1. **需求是锚点**：任何功能先有 `REQ-xxx` 编号，roadmap 任务关联它；不要脱离需求直接写代码。
2. **实施前对齐**：开工前读需求卡描述＋验收标准＋`decisions.md` 相关决策，有歧义先澄清。
3. **实施后回写**：
   - 卡状态流转 + 实施记录追加；
   - 闭环时同步 `requirements.md` 状态列 ＋ `roadmap.md` 实施记录。
4. **决策留痕**：做出影响架构/范围的选择，写一条 `decisions.md` 的 DEC 记录。
5. **待确认即显式**：未决项集中记在 `decisions.md` 末尾「待确认事项」，不在脑子里。
