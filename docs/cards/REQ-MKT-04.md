## 1. 需求描述
> 用户原话：*"堆道琼斯，恒生指数，纳斯达克这部分进行一下布局调整，名称左对齐，金额右对齐，涨跌右对齐，尽可能都等宽吧，阅读体验更好"*

其他市场（美股 / 港股 / 日韩股，共 6 支，2 行 × 3 组网格）当前为内联文字（`name price change` 相邻左对齐成组），层级低、阅读时数字不在同一垂直线上。用户要求改为**表格式对齐**：
- **名称**：左对齐（占左侧剩余空间，可截断）。
- **金额（价格）**：右对齐，固定等宽列。
- **涨跌幅**：右对齐，固定等宽列（与金额列等宽，保证两列数据纵向对齐成线）。
- 目标：阅读体验更好，各数值列"等宽"对齐。

## 2. 验收标准（Acceptance Criteria）
> 注：AC 于 2026-07-15 二次打回后按用户最新规格重定（三列固定宽、名称左对齐、数值/涨跌右对齐）。
- [x] AC1：每组结构为「名称(左对齐) 数值(右对齐) 涨跌(右对齐)」三列，三列均固定宽 → 紧贴读为一组。
- [x] AC2：**名称列**固定宽 = 最宽名称「韩国KOSPI」的宽度（`w-[4.5rem]`＝72px），左对齐，短名称右侧留白、不截断。
- [x] AC3：**数值列**右对齐，固定宽 = 10 位数字宽（`w-[10ch]`）；**涨跌列**右对齐，固定宽 = 6 位字符宽（`w-[6ch]`）。
- [x] AC4：三列宽度恒定 → 6 支指数在两行三列网格中，名称左缘、数值右缘、涨跌右缘各自跨行纵向对齐成线；外层 `grid grid-cols-3` 三组一行平均分布。
- [x] AC5：红涨绿跌着色、骨架占位（加载中 `animate-pulse`、失败态静态）、`ov-anim` 入场动画均保留，布局零位移；仅改 `OtherIndexText`，tsc 无新增报错、无 `pageerror`。

### 🔧→🧪 重做（2026-07-15 用户打回）
- **打回原因（用户原话）**：*"虽然我让这些信息等宽，但现在出现了信息过宽，每一个等宽，信息之间的紧密关系没有了。道琼斯 指数 涨幅 这样是一组信息才对。但是目前看所有信息都是独立的了。"*
- **根因**：初版 `name flex-1` 让名称占满剩余空间、数值被推到单元格最右，名称与自身数值之间出现 ~30px 大间隙；数值列 `w-20`(80px) 过宽，三者各自独立成"列"，破坏了"指数 价格 涨跌"成组的阅读关系。
- **重做方案**：`OtherIndexText` 改为 `flex items-center justify-end gap-1.5`——名称 `shrink-0` 自然宽（紧邻其数值，间隙仅 6px，读为一组）；金额 `w-16` / 涨跌 `w-14` 固定宽、`text-right`、`shrink-0`（整体靠右 → 各单元格内金额/涨跌右缘跨两行对齐成列）；去掉 `flex-1` 与 `truncate`（名称不再被拉伸/截断）。骨架/动画/红涨绿跌保留。
- **🧪 自测（重做）**：tsc 对 OverviewPage 无新增报错；无头 Chrome 加载 localhost:1420：6 行全中；`nameRightToPriceLeftGap=6`（名称紧贴数值，成组）；`justifyContent=flex-end`；各单元格内 price/change 右缘跨两行一致（道琼斯&恒生指数=250/312、纳斯达克&日经225=466/528、标普500&韩国KOSPI=681/743）→ 数值列仍对齐；`nameTruncated=false`；`PAGEERRORS=0`。
